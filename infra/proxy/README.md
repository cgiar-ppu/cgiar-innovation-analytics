# Synapsis Proxy — Ops Runbook

## Architecture Overview

```
Mac Mini (apps on localhost ports)
    |
    | autossh reverse tunnel (SSH)
    | ~/.ssh/synapsis-proxy
    v
EC2 (eu-central-1) — nginx HTTPS reverse proxy
    |
    | HTTPS (443), wildcard cert via certbot-dns-route53
    v
Internet — synaptic.synapsis-analytics.com
           *.synaptic.synapsis-analytics.com (e.g. p7777.synaptic.synapsis-analytics.com)
```

The Mac Mini maintains a persistent SSH reverse tunnel to EC2 via an autossh LaunchAgent. Nginx on EC2 terminates TLS, enforces HTTP basic auth, and proxies requests back through the tunnel to the appropriate local port. Port subdomains (`p7777`, `p8080`, etc.) map to the corresponding localhost port on the Mac.

**Key files:**
- `infra/proxy/template.yaml` — CloudFormation stack (`synapsis-proxy`, eu-central-1, profile `ai-sandbox`)
- `infra/proxy/setup-tunnel.sh` — fetches EC2 IP from CloudFormation, generates the LaunchAgent plist
- `infra/proxy/nginx/synaptic.conf` — nginx site config
- `infra/proxy/nginx/nginx-http.conf` — nginx http-block config
- `~/Library/LaunchAgents/com.synapsis.proxy-tunnel.plist` — live tunnel config (generated by setup-tunnel.sh)

## Common Operations

**Check if the proxy is working:**
```bash
curl -sk --user smith:PASSWORD https://synaptic.synapsis-analytics.com/
```

**Check tunnel status:**
```bash
ps aux | grep autossh
```

**SSH into the EC2 instance:**
```bash
# Get the current IP first
aws cloudformation describe-stacks \
  --stack-name synapsis-proxy \
  --profile ai-sandbox \
  --region eu-central-1 \
  --query 'Stacks[0].Outputs'

ssh -i ~/.ssh/synapsis-proxy ec2-user@<EC2_IP>
```

**Check nginx logs on EC2:**
```bash
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

## Troubleshooting

### 502 Bad Gateway
The SSH tunnel is not connected. Steps:
1. Check if autossh is running: `ps aux | grep autossh`
2. If the EC2 IP changed (e.g. after a CloudFormation deployment), see [After Instance Replacement](#after-instance-replacement) below.
3. If autossh is running but the tunnel is broken, reload the LaunchAgent:
   ```bash
   launchctl unload ~/Library/LaunchAgents/com.synapsis.proxy-tunnel.plist
   launchctl load ~/Library/LaunchAgents/com.synapsis.proxy-tunnel.plist
   ```

### Site completely down after CloudFormation deployment
Most likely cause: CloudFormation replaced the EC2 instance, so the IP changed and the tunnel is connecting to a stale address. Follow the [After Instance Replacement](#after-instance-replacement) checklist.

### ERR_CONNECTION_TIMED_OUT on port subdomains
Do not append the port number to the URL. The port is encoded in the subdomain.

Correct:
```
https://p7779.synaptic.synapsis-analytics.com/
```
Incorrect:
```
https://p7779.synaptic.synapsis-analytics.com:7779/
```

### HTTP 413 Request Entity Too Large
Upload exceeds the 50 MB limit (`client_max_body_size 50m` in nginx config). Either reduce the upload size or increase the limit in `nginx/synaptic.conf` and redeploy.

### Cert renewal failure
The certbot systemd override ensures the venv certbot binary is used instead of the system one. Check on EC2:
```bash
sudo systemctl status certbot-renew.timer
sudo journalctl -u certbot-renew --no-pager -n 50
```

## After Instance Replacement

Run these steps in order whenever CloudFormation replaces the EC2 instance (new IP).

1. **Get the new IP:**
   ```bash
   aws cloudformation describe-stacks \
     --stack-name synapsis-proxy \
     --profile ai-sandbox \
     --region eu-central-1 \
     --query 'Stacks[0].Outputs'
   ```

2. **Regenerate the LaunchAgent with the new IP:**
   ```bash
   ./infra/proxy/setup-tunnel.sh
   ```

3. **Restart the tunnel:**
   ```bash
   launchctl unload ~/Library/LaunchAgents/com.synapsis.proxy-tunnel.plist
   launchctl load ~/Library/LaunchAgents/com.synapsis.proxy-tunnel.plist
   ```

4. **Remove the stale host key (if SSH refuses to connect):**
   ```bash
   ssh-keygen -R <OLD_IP>
   ```

5. **Verify:**
   ```bash
   curl -sk --user smith:PASSWORD https://synaptic.synapsis-analytics.com/
   ```

## Important Notes

- **UserData runs once.** Nginx config, TLS certs, and htpasswd are all provisioned automatically on first boot (instance creation). They are not re-applied on stack updates that don't replace the instance.
- **Tunnel throughput.** `IPQoS=throughput` is set on the tunnel, giving ~2 MB/s vs ~92 KB/s with default QoS settings.
- **Static asset caching.** Nginx caches static assets on EC2 for 7 days to reduce tunnel load.
- **CI/CD.** `.github/workflows/deploy-proxy.yml` triggers on push to `main` when files under `infra/proxy/**` change. This deploys the CloudFormation stack.
- **Unrelated workflow.** The "Deploy Synapsis Agent" workflow (`deploy.yml`) is completely separate from this proxy. Its failures have no bearing on proxy operations — ignore them.
